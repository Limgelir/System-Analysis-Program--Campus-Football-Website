## 基本规则

- 已执行的迁移文件绝对不能修改、重命名或删除；
- 新迁移按 `0002_clear_name.js`、`0003_another_change.js` 连续编号；
- 文件名、导出的 `version` 和 `name` 必须一致；
- 每个迁移必须导出 `description`、`rollback` 和 `async up(connection)`；
- 尽量使用可重复检查的 SQL，并在修改数据前先验证数据是否满足新约束；
- MySQL 的多数 DDL 会隐式提交，不能依赖事务自动回滚表结构变更；
- 删除字段、改类型、批量改数据等高风险迁移，执行前必须备份并在 `rollback` 中写清恢复步骤；
- 不提供自动 `down` 命令，避免误操作造成二次数据损坏。需要回退时按照迁移文件中的说明和备份人工处理。

## 迁移模板

```js
module.exports = {
  version: '0002',
  name: 'clear_migration_name',
  description: '说明本次变更的目的',
  rollback: '说明如何利用备份或反向 SQL 恢复',
  async up(connection) {
    await connection.query('ALTER TABLE example ADD COLUMN note VARCHAR(255) NULL');
  }
};
```

阶段 5B 新增：`0007_reserve_national_grade` 扩展账号当前级别、目标级别与赛季级别快照；`0008_shanghai_fa_registration` 为账号新增独立是/否标记，存量统一初始化为否。二者可在已有业务数据上前向升级，不改写旧迁移；字段已存在时不会将后来填报的“是”再次重置。全新库结构同时维护在 `db/final_schema.sql`。

在 `backend` 目录运行：

```powershell
npm run migrate:status
npm run migrate
npm run migrate:check
```

- `migrate:status`：只读显示当前版本；
- `migrate`：取得数据库锁，依次执行所有待执行迁移；
- `migrate:check`：只读检查迁移是否完整，缺失、乱序或校验和变化都会失败。

应用启动时也会执行只读检查。存在待执行迁移时，后端会拒绝启动并提示先运行 `npm run migrate`。

### 阶段 8：报告分区版本与退回

`0011_report_revision_history` 为两个报告分区增加 `returned` 状态，建立 `report_section_states` 和 `report_section_history`。升级前停止应用写入并备份数据库及完整上传目录；已有业务行与密码不变。迁移逐分区保留当前可证明的基线、负责人、原提交时间；有原操作事件时保留真实提交人，否则明确记为未知，不伪造更早版本。迁移完成后重复执行不重复生成历史。

新提交和管理员直接修订增加显示版本，普通保存、退回、图片操作也记录独立修订号用于并发检查（管理员图片修订同样生成新版本）。业务事务同时更新当前内容、分区状态和追加快照；退回只开放对应分区，原提交时间和赛程/岗位锁定保留。新建空赛程尚无写入时允许状态行延迟创建，读取返回 V0 / revision 0；已有内容或历史的赛程不允许删除。

前后端须同时升级，旧客户端缺少 `If-Match` 时写入返回 409。历史文件继续保存在上传目录并通过鉴权历史接口访问，备份和数据审计已包含这些引用。业务接口不支持修改/删除历史；具有数据库管理权限的运维和显式整库演示重置不属于这个接口级只追加保证。不要重新导入初始化 SQL 或运行样例重置来代替增量迁移。


### 阶段 9—11：登录保护与安全事件

`0012_login_security_events` 新建 `login_security_buckets` 和 `security_events`，不重置原账号、密码、赛季或报告。登录防护桶持久化，安全事件严格列白名单，账号/IP 为 HMAC 键；事件保留不依赖业务账号删除。新库基线同步增加表，旧库只用前向迁移，重复迁移不会重复修改业务行。

升级前备份 SQL 与完整上传目录；应用新后端前执行迁移、检查和数据审计。回退优先前向修复，不为回退代码删掉审计记录。阶段 12 再确定安全日志保留和归档策略。

仓库级保护：`node backend/scripts/checkMigrationHistory.js` 比较 HEAD 中既有迁移内容；CI 使用 PR 基准或推送前提交，拒绝改写/删除已发布迁移，兼容 CRLF/LF。数据库内的版本、连续性和 SHA-256 校验仍由迁移工具执行；隔离集成测试覆盖新库、存量业务升级、重复执行和历史数据不变。
