# 阶段3：三端界面与交互规范

沿用同济校徽和蓝白风格，保留 `frontend`（管理员/裁判）与 `player-frontend`（球员/公开查询）两个工程和各自身份空间。

## 共享实现

| 文件 | 职责 |
| --- | --- |
| `shared-ui/theme.css` | 品牌色、文字、表单、按钮、卡片、表格、状态、弹窗和响应式规则 |
| `shared-ui/AppShell.vue` | 校徽、角色导航、手机菜单、当前入口、跳到主要内容和页脚 |
| `shared-ui/PageState.vue` | 加载、空数据、错误及重试入口 |
| `shared-ui/ListPagination.vue` | 结果总数、页码、每页条数、上一页/下一页；原站组件保留兼容导出 |
| `shared-ui/interaction.js` | 未保存内容保护、原生表单行内错误、标签关联、弹窗焦点和页面标题 |

两个工程在 `main.js` 中引入共享主题并安装交互插件；Vite 对 Vue/Vue Router 去重，避免共享源码引入第二份运行时。原站管理/业务路由按页加载，入口无需同时下载全部页面。

原页面样式放入 `@layer legacy`，保留各页业务布局；无层的共享主题统一基础控件和反馈，避免继续靠每页提高选择器权重覆盖颜色。现有重复布局没有全部删除，后续页面改动应优先使用共享变量和组件，不再建立另一套配色。两份校徽静态资源继续由各自站点提供。

## 视觉与导航

- 深蓝 `#123b6d`，主按钮蓝 `#1e5ca8`，浅背景 `#f3f6fa`，正文 `#172b45`，辅助文字 `#52657a`。
- 桌面侧栏、手机折叠菜单；900px以下切换。表单和按钮通常至少44px高；勾选控件使用带文字的标签区域。
- 管理员按赛事工作、资格与申请、人员管理分组；当前启用赛季和正在查看的历史赛季分别说明。
- 裁判围绕赛季注册、选派报名、执法与报告、统计和设置组织入口。报名和正式选派继续分别显示。
- 球员围绕本人资格、球队报名与管理、公开球队与赛程和账号设置组织入口；首页分开显示正式参赛队伍和报名管理。
- 状态保留文字；手机表格在容器内滚动，页面主体不横向溢出。长名称和错误允许换行。
- 支持可见键盘焦点、跳到主要内容、菜单展开状态、弹窗 Tab/Shift+Tab 循环、Escape关闭与焦点返回。用户设置减少动画时关闭动画。

## 表单与未保存内容

业务表单显式使用 `v-draft="{ value, resetKey?, ready?, dirty? }"`。插件只在内存里比较当前值和基线，不把密码、名单、学籍材料或报告草稿存入浏览器持久存储。

- 默认比较 `value` 快照；文件按名称、大小、修改时间比较。已有业务脏状态时可传 `dirty`，例如球队名单和报名意向。
- 异步加载期间传 `ready: false`；加载完成后建立基线。`resetKey` 仅在服务端数据确实更新/切换时改变；不能随着每次键入改变。
- 保存成功后更新服务端基线、增加保存计数，或调用 `$markDraftSaved(element)`。请求失败和版本冲突不清空输入。
- 路由跳转、浏览器关闭/刷新会检查未保存修改；页内关闭、重载、记录/赛季切换在实际丢弃输入之前调用 `confirmDraftLeave`。取消时保留输入和原选项。
- 仅改变同一路径同一查询的锚点不丢弃页面内容，不触发离开确认。确认弃用后，同一次关闭/跳转不重复询问。
- 原生 `required`、类型、范围等约束失败时，在字段旁显示错误并关联 `aria-describedby`；有效输入清除错误。后端业务错误和冲突继续使用页面内提示。
- 登录表单不提示离开草稿；账号注册、资料维护、报名意向、审核说明、比赛/报告编辑、名单导入等业务输入接入保护。

保存草稿、提交审核、正式提交、报名和正式选派的业务动作仍使用不同文案。危险操作沿用原确认机制，球员撤回学籍/球队申请增加明确确认。

## 赛程列表上下文

`scheduleReturnQuery` 只传递以下查询参数：`season_id`、`match_type`、`date_from`、`date_to`、`source_type`、`report_status`、`page`、`page_size`。

列表 → 详情 → 报告 → 返回详情 → 返回列表保持这些参数；浏览器后退同样恢复筛选和分页。直达详情没有列表上下文时，以比赛所属赛季返回列表。详情加载期间禁用返回按钮，避免尚未读到历史赛季就返回错误列表。其他参数不透传到赛程筛选。

## 保持的业务边界

后端权限、赛季审核、未来7天报名窗口、开球截止、多选意向、报名优先、场地必填、报告锁定、名单生效时间、版本校验与公开结果发布规则保持。请求序列保护继续防止较旧响应覆盖新页面。界面行为测试见[界面测试](../frontend/tests/)。
