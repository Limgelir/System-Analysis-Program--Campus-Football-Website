# 比赛时间与同场序替换（本地验收）

## 已确认规则

- “比赛时间”支持 `15:00` 或 `15:00-16:00`，精确到分钟。结束时间选填，仅用于展示，必须晚于同日开始时间，不支持跨午夜。
- 开赛判断、报名截止、删除截止及排序继续使用开始时间。历史单时间和时间待定数据保持原有语义。
- 同场序按同一赛季、同一赛事匹配。单场添加与批量导入均须明确确认后才替换；弹窗展示原、新日期、时间、对阵及场地。
- 原赛程和新赛程都必须尚未开赛，且原赛程报告未开始填写。待定开始时间不允许替换。提交时使用服务器中国标准时间重新检查，恰好开赛即拒绝。
- 替换保留赛程ID、场序、裁判安排设置、已选派人员、报名及历史。仅更新日期、开始/结束时间、对阵和场地；日期或球队变化时沿用既有规则重新解析比赛名单。
- 批量新增及替换共用事务。取消不写入，任何一场失败整批回滚。签名预览绑定管理员、原始输入和30分钟有效期，确认时重查版本及赛季、球队和报告状态。

## 本地入口

构建管理/裁判端后，在 `backend` 运行 `npm run preview:schedule-time`。

- 管理员：`http://127.0.0.1:5230/admin-login`。
- 裁判：`http://127.0.0.1:5230/referee-login`。
- 独立随机测试库、虚构球队和裁判；账号与随机密码写入被Git忽略的 `.cache/schedule-time-local-acceptance.md`。
- 初始赛程R1为次日15:00-16:00，已有裁判报名及正式选派。
- 样例 `.cache/比赛时间验收-替换与新增.csv` 包含R1替换和R2新增；错误样例包含跨午夜时间。
- 停止时创建 `.cache/schedule-time-preview.stop`，服务自动关闭并清理本次随机数据库与临时上传目录。

## 手动验收

1. 管理员进入赛程管理，单场填写R1、16:00-17:00。取消确认后检查原记录；再次添加并确认，检查时间和对阵更新。
2. 上传“替换与新增”样例，预览应明确标记新建/待确认替换。核对弹窗，先取消，再确认，检查只新增一场。
3. 裁判进入选派报名，选择“校内邀请赛”，应看到完整时间段、已报名、已选派，且可看到开始时间变化提示，无需重新报名。
4. 编辑赛程为单时间16:00，保存后结束时间应消失；改回16:00-17:00后显示恢复。23:00-01:00、16:00-15:00、15:00-15:00均应拒绝。
5. 下载模板核对“比赛时间”和填写说明；原“开球时间”表头仍兼容。

## 实现与部署边界

新增增量迁移 `0035_schedule_match_end_time`：只增加可空 `match_end_time` 及同日先后约束，不回填历史数据。API读取保留 `match_time` 为开始时间，另返回 `match_end_time`。表单和导入可把时间段放入 `match_time`，也接受显式起止字段。编辑时漏传两个字段会保留原值，明确输入单时间会移除结束时间。

新增报告历史快照记录结束时间；已有历史快照不改写。裁判报名、赛程列表/详情、选派面板、履历、工作台、报告、球员公开赛程及CSV导出同步显示时间段。
