# 赛事与纪律约定（0020）

## 赛事与场序

每赛季初始赛事列表为空。管理员在原球员报名设置中添加赛事：预设大联赛、新生杯、四平足协杯、嘉定足协杯，或选择其它并填写名称。`league_type` / `match_type` 名称不可在保存后重命名或删除，注册与报名窗口继续使用原逻辑，未开放报名不影响管理员安排比赛。最多100项，每项名称为1—50个字符。

数据库保留原名称关联形式，将固定枚举改为文本；`season_competitions.id` 是纪律账本的赛事标识。旧足协杯记录原样保留，不自动拆分。仅迁移已有球队/赛程实际涉及的赛事，空赛季不补默认赛事。旧演示赛事没有纪律参数时可一次性补全，不追算迁移前报告。

场序 `field_order` 为1—50字符文本，首尾去空格，拒绝控制字符；按赛季+赛事精确唯一，区分大小写与前导零。数字输入兼容转换为字符串，API返回字符串。时间排序后按自然场序、原字符串、ID排序，`A2` 在 `A10` 前。报告开始后继续锁定场序和其他核心字段。

## 规则和正式版本

赛事必填 `yellow_threshold,yellow_suspension,red_threshold,red_suspension`，均为1—100整数。分别表示累计N张、停M场；首次正式报告后锁定。停赛作用域为赛事+球队+永久球员ID，旧未关联名单只按旧名单身份处理，不凭姓名或学号合并。不同球队、赛事、赛季互不累计。

- 主裁正式提交或管理员正式修订计入纪律。草稿不计，退回保留上一正式版本，重新提交替换原记录。
- 新牌类型 `second_yellow_red` 表示两黄罚下，按1红累计，同一球员本场的黄牌全部排除；原明细保留。最多一次罚下；两条普通黄牌必须同时明确两黄变红，避免误计。
- 黄红同场触发取停赛场数的较大值，两种牌均标记为触发牌种。服满后只清触发牌种，其他牌保留。
- 仅同队本赛事、晚于处罚来源比赛的已完成比赛正式提交主裁报告才执行1场。未提交的未来/逾期比赛仅做预测，不扣实际剩余场数。重复提交、修订同一报告不会重复扣减。
- 补报、更正可能改变处罚依据。账本保存首次发布时的执行记录，不把此前没有执行记录的比赛追认为已服满；发现冲突显示待核对提示，由管理员填写原因纠正剩余场数。
- 停赛中仍出现吃牌记录时，不自动视为已服满，提示管理员核对。
- 全部清零仅影响选中赛事，清除累计两色牌和未完成停赛，保留报告、历史计牌与人工操作。以清零时刻作为阶段分界，之前比赛的晚报/修订不进入新阶段；本阶段之后的比赛重新累计。

未来名单按当前未正式完成的赛程顺序估算，两端会提示改期、补交报告可能改变名单。已正式完成比赛不展示当前预测为历史事实。裁判只可读取自己获派比赛双方名单；登录球员可在球队未来赛程看到双方名单，匿名公开页面不展示纪律明细。

## 接口

原 `GET/PUT /api/player-admin/season-settings/:seasonId` 增加四个纪律规则字段，读取还返回 `presets`、每项 `rules_locked`。提交不要包含这些只读字段或赛事ID。原设置修订号 `If-Match` 继续有效。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| GET `/api/competitions?season_id=...` | 管理/裁判登录 | 实际赛事列表及预设名称 |
| GET `/api/public/competitions?season_id=...` | 公开 | 球员侧筛选选项 |
| GET `/api/competitions/matches/:id/discipline` | 管理员或本场当值裁判 | 双方预计停赛名单 |
| GET `/api/competitions/:id/discipline` | 管理员 | 分队表、历史计数、明细、异常和修订号 |
| POST `/api/competitions/:id/discipline/adjust` | 管理员 | `{key,remaining,reason}`，剩余场数0—100 |
| POST `/api/competitions/:id/discipline/reset` | 管理员 | `{confirm_name,reason}`，精确确认赛事名 |

纠正/清零携带表格读取的纪律 `If-Match`；任何正式报告变化会推进该修订号，旧表操作返回409。原因必填1—500字。纠正为0视为服满；恢复未完成场数保留处罚来源与触发牌种。已结束赛季只读。

原球员 `/api/player/team-results/:id` 的比赛项附加 `discipline`，含 `configured,projected,suspensions`。返回名单仅含展示所需的姓名、号码、队伍、原因与预计剩余场数，不返回学号、联系方式或报告私有内容。

## 数据一致性

赛事列表和设置只包含已添加或已有实际配置/业务数据的赛事。旧版自动生成、未启用且无规则、时间窗口或业务引用的空记录不算已添加；统一从选项与必填设置中排除，原记录保留，之后显式添加同名赛事可复用原ID。已有球队、赛程、报名或纪律历史不能因未配置新停赛规则而消失。裁判过往执法经历的类型选项独立于当前赛季赛事。

0020新增 `competition_discipline_events` 记录正式报告的有效版本、清零与纠正；每个报告至多一个有效事件，引用不可变报告历史。原报告历史继续保存每次修改。报告公开、纪律更新在同一数据库事务内，按赛事行加锁串行化跨比赛累计，并使用 READ COMMITTED 读取最新已提交纪律记录。

迁移0001—0019不变。生产升级只能执行新增迁移，不用初始化SQL覆盖旧库。数据库变成文本场序并写入自定义赛事后，旧版本代码不兼容；回退需匹配的数据库与上传备份，优先前向修复。
