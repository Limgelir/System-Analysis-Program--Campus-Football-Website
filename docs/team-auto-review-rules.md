# 球队报名自动审核规则

## 撤销报名通过

管理员在“球队报名审核 → 查看球队申请”中，对已通过的线上首次报名填写必填原因，再点击“撤销报名通过”并确认。Excel 导入和单独的中期名单变更不提供此操作。

撤销后原申请显示“已撤销通过”，沿用当前负责人、队长和最新正式名单。原因向本队成员展示并发送站内通知；负责人／草稿队长在报名时间内可编辑原申请并重新提交，仍需管理员再次批准。报名未开放或已截止时不能编辑、提交或申请人工审核，退回也不延长已撤销球队的报名期限。

已有赛程、比赛名单、比分、球队编号与操作历史保留；撤销期间不计入当前正式参队统计，也不能新排赛。重新通过新增正式名单版本，已有赛程继续使用撤销前选定的名单。原来的名单变更草稿因正式版本变化失效，可以撤回后重新创建。

## 报名限制


管理员在“赛季管理 → 球员报名设置”添加或编辑比赛类型时，可分别填写以下限制。每个赛季的每个赛事独立设置，没有全站隐含默认人数。

| 设置 | 字段 | 判断 |
| --- | --- | --- |
| 大名单最低人数 | `min_players` | 实际人数 ≥ 最低人数 |
| 大名单最高人数 | `max_players` | 实际人数 ≤ 最高人数 |
| 最多学院数 | `max_colleges` | 不同学院数 ≤ 上限 |
| 最多外援人数 | `max_foreign_players` | 外援人数 ≤ 上限 |
| 最多运训人数 | `max_sports_training_players` | 运训人数 ≤ 上限 |

- 所有字段均选填，空白／null 表示不限制该项；上下限可以只填写其中一个。
- 0 是有效限制，例如外援上限为 0 表示不允许外援。最低人数 0 不增加最低要求；原来至少一名队员、恰好一名队长等完整性规则仍然适用。
- 只接受非负整数；上下限都填写时，最低人数不能高于最高人数。边界人数可以通过。
- 学院使用账号当前生效的学院；球员申请修改学院须经管理员审核后才生效。球员当季学籍资格仍须通过才能发布名单。
- 所有名单成员均计入学院统计，包括外援和运训。学院名去掉首尾空格后精确去重；“建筑学院”和“建院”视为两个学院。
- 外援和运训使用大名单中相应标记。一个人同时勾选两项时，在两项中各计一人；名单总人数只计一人。仅任负责人、未列入大名单的人不计入。
- 不限制同时参加的球队数量；其它正式参队情况供管理员核对，不自动据此判失败。
- 已配置学院上限却缺少审核通过学院资料时，不将其当作“0 个学院”直接放行，页面指出资料缺失。管理员可核验学籍，或通过独立的人工通过操作说明例外。

## 2. 报名、变更与人工审核

线上首次报名和正式队伍的名单变更均执行自动审核。保存草稿会显示当前已保存名单的检查结果；正式点击提交时在服务器重新检查。

任一限制不符合，申请保存为“自动审核失败”，一次列出全部失败原因、实际数量、规则值和检查时间，保存当时名单及操作历史。管理员列表默认显示全部状态，可单独筛选自动失败。自动失败不会建立正式球队，也不会改变名单变更申请对应的旧正式名单。

符合全部限制后进入“待审核”，等待管理员人工批准。普通批准前按最新规则和最新球员资料重新检查：旧页面遇到变化时要求刷新；刷新后仍不符合则记为自动失败。

人工审核例外：**管理员可以人工通过自动失败的申请，原因必须填写。**

- 自动失败详情显示独立按钮“人工通过自动审核失败”，普通“通过”接口不会悄悄绕过限制。
- 保存原因、管理员 ID、通过时间、原自动失败记录以及人工通过时的最新检查结果。即使规则后来放宽，仍可展开查看原失败记录。
- 人工通过可在球队报名或名单修改窗口截止后执行；赛事仍须处于启用且赛季未结束的可审核状态。
- 该例外只豁免本轮新增的数量／学院限制。账号启用、当季学籍资格、号码与队长完整性、同名球队、名单基础版本、访问权限和防重复提交校验仍然有效。
- 人工通过首次报名建立正式球队；人工通过名单变更按原机制立即发布新批次并保留历史批次。

失败后的修改仍遵守原窗口与补正规则：窗口内负责人／队长可修改重提；窗口外不自由开放增删人数。管理员可以对失败申请“退回补正”，指定允许等人数替换的球员。补正后再次自动失败会保留这次指定替换权限；其他人仍锁定。增加或减少人数须统一重开窗口。自动失败的名单变更仍占用唯一进行中的变更申请，撤回后才能新建。

管理员特殊 Excel 导入保留既有例外，不受这四类自动限制或线上报名窗口约束。已导入正式队伍后来走球员线上名单变更时，该次线上申请照常检查。

## 3. 管理员审核详情

每位名单球员展示：姓名、学号、当前学院、学籍审核确认学院、资格状态、外援／运训标记和其它正式参队情况。

其它参队范围是**同一赛季全部比赛类型的当前有效正式名单**，逐项显示“已参加某某队（比赛类型）”。上方人数汇总统一为“本赛季其它已通过球队数（全部赛事）”，与下方明细使用同一范围，包含同类及其它类型赛事。排除正在审核的本队、仅担任负责人的关系、待审／草稿申请及已退出的旧名单；没有其它有效参队时显示“并无参加其它队伍”。这些信息随当前名单更新，审核令牌也包含参队变化，旧审核页面不能直接越过变化继续批准。

每位球员提供“姓名学籍详情”按钮，展开学籍资料和受管理员权限保护的截图。原材料已清理时说明不可用。普通队员不会因此获得其他人的学号、学籍图片、审核快照或内部审核记录。

## 4. 已有数据处理

- 新迁移给已有赛事的五个设置全部填 null，含义为不限，不猜测既有文本规则。
- 已有账号、密码、球员、正式球队、名单批次、待审申请和比赛记录保留。
- 后续新增／修改限制只作用于后续报名、名单变更及待审申请批准前重查。
- 不自动取消已通过球队资格、不重写旧正式名单、不修改赛程。
- 已有待审申请没有自动审核记录时，批准前补做检查。原先退回补正后再次待审的申请保留已获准的补正范围。
- 已发布迁移 `0001`—`0022` 保持原内容；升级采用新增 `0023`，不重新导入初始化 SQL。


足球特长生、标签开关、组合人数上限和性别校验见 [球员 API](player-api-contract.md)。
