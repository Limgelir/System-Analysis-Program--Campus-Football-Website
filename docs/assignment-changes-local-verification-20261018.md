# 裁判选派随时调整与时间重合提醒：本地验收

日期：2026-10-18。功能已完成本地自动化验收，用户已确认本地验收通过并授权提交、推送及服务器更新。本文记录本地验收，服务器发布结果另行记录。

## 已确认的业务规则

- 管理员在报告未开始、草稿、已提交或已退回时，都能更换、清空、补选人员；第四官员、裁判监督需求和普通／五人制安排也可调整。
- 同场岗位互斥、候选人资格、权限和并发版本校验继续生效。切换安排类型沿用原确认流程，并清理不适用的报名意向。
- 时间重合只提醒，不阻止保存，也不增加确认步骤。按同一天、同一系统账号或同一非系统名单编号判断，跨赛事、跨赛季同样提示；同名不同编号不会混为一人。
- 两场都录入结束时间时，按区间相交判断；首尾相接不算。任一场缺少结束时间时，仅同开球时刻提醒。时间待定不推算重合。
- 比分、点球、进球、红黄牌和记录单图片保留。被替换岗位的执法数据及监督评分进入原报告历史，当前数据清空，由现任人员补填；更换裁判监督清空当前监督评分；切换普通／五人制清空当前执法数据及评分。
- 受影响的已提交报告分区自动退回；只更换裁判监督时，裁判员分区状态和数据保持不变。原提交记录保留；取消监督岗位后仍可查看既有监督历史。

## 实现与数据升级

`0036_assignment_report_handover` 为真实操作事件增加原岗位快照，将原岗位外键改为可空并在删除原选派时置空；原姓名、身份、操作人和报告分区前后快照保留。交接与选派保存处于同一事务，并更新报告分区版本，拒绝旧页面覆盖。未填写的空报告和相同选派重复保存不生成多余交接历史。

历史迁移未改写。既有数据库使用增量迁移，不能重新导入初始化 SQL。本地验收阶段只在随机隔离验收库运行迁移，未修改日常库及线上库；用户验收后已完成生产发布，见[上线记录](https://github.com/Limgelir/TJ-RefWeb/blob/1013304/docs/assignment-changes-production-verification-20261018.md)。

## 手动验收

在 backend 目录运行 `npm run preview:assignment-changes`，打开 http://127.0.0.1:5238/admin-login，登录信息见 `.cache/assignment-changes-local-acceptance.txt`。全部数据为虚构，使用随机独立测试库，仅监听本机。

1. 裁判选派 → 全部赛程 → 裁判选派调整本地验收。
2. A01 的两个报告分区已提交，仍能修改人员及配置；查看其历史可见原执法数据和评分。
3. A01 为 15:00–17:00，A02 为 16:00–18:00；选同一个人会显示其另一比赛及岗位，直接保存成功。
4. A03 为 17:00–18:00，与 A01 首尾相接，不提示重合。
5. 更换 A01 第一助理，保存后原助理数据在历史中，当前岗位待填写，相关已提交分区退回。只更换裁判监督则保留裁判员分区状态。
6. 取消监督或第四官员、切换五人制，保存并刷新，检查岗位和报告模板同步。

在 `.cache` 中创建 `assignment-changes-preview.stop` 文件可停止预览并清理本次隔离库。
