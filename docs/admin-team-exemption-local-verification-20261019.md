# 管理员直接编辑球队：自动审核与资格豁免本地验收

日期：2026-10-19。用户要求先在本地验收，并明确确认“同时跳过球员资格，保留名单基本规则”。用户已确认本地验收通过，授权提交、推送并随后更新服务器；已完成生产发布，见[上线记录](https://github.com/Limgelir/TJ-RefWeb/blob/1013304/docs/admin-team-exemption-production-verification-20261019.md)。

## 行为

- 仅“正式球队与名单 → 管理员修改球队”入口豁免。管理员可直接保存超过赛事人数、学院数、外援、运训、足球特长生及合并人数限制的名单，不再出现截图中的“学院数量为4，要求不多于2”保存失败。
- 球员当季学籍未通过或资格已撤销、账号已停用、性别未填写均不阻止查询添加及保存；负责人也可选择已停用的现有账号。界面仍如实显示资格及账号状态，保存不更改学籍审核或账号状态。
- 保留账号存在、有效字段、号码非负整数且不重复、同一球员不重复、恰好一名队长、同赛事队名唯一等基本规则。
- 保留管理员权限、当前启用且未结束的赛事、报名撤销状态、进行中的名单或角色变更处理、旧页面并发检查及事务回滚。
- 仍生成正式名单新批次、同步赛程队名并保留旧名单及报告；操作历史保存实际规则检查结果和管理员豁免依据，不将超限伪装成自动审核通过。
- 普通球员报名、提交名单及管理员普通报名审核、人工通过入口继续使用原资格和审核规则。本次无需数据库迁移。

## 本地验收

- 管理员：<http://127.0.0.1:5228/admin-login>，账号 `team-admin`。
- 密码与完整步骤：`.cache/admin-team-local-acceptance.txt`。
- 本轮使用单独的本机 MySQL 实例（3339端口），网站只监听127.0.0.1，业务数据为随机隔离库中的虚构样例。未对日常业务库执行迁移或修改，未连接线上服务器。

1. 进入“正式球队与名单”，选择“四学院超限验收队”，打开“管理员修改球队”。现有4名球员来自4个学院，赛事最多2个学院、最多1人。修改颜色、号码或队名，保存应成功。
2. 添加 `ADM-LOCAL-0`（当季学籍未通过），填写未使用号码，勾选外援、运训及足球特长生。赛事各单项与合并人数上限为0，仍应保存成功。
3. 添加 `ADM-LOCAL-4`（已停用且未填性别），填写未使用号码，保存应成功；也可将其设为负责人。停用状态与未填性别显示应保持真实。
4. 尝试重复号码或移除唯一队长，保存应被基本规则拦截。修正后可以保存，重新载入应保留修改。
5. 另有“可编辑示例队”“可撤销退回队”“可恢复通过队”，用于检查改名、换负责人、赛程同步及撤销误操作。

预览脚本：在配置了本机测试数据库连接的环境中运行 `npm run preview:admin-teams`。停止时创建 `.cache/admin-team-preview.stop`；脚本仅清理自身随机库及临时上传。
