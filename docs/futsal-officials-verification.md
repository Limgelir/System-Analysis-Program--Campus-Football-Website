## 已确认的规则

- 管理员新建、编辑赛程或调整选派时，可选择“是否采用五人制裁判安排”，旧比赛默认普通安排。
- 五人制使用裁判员、第二裁判员、计时员三岗，必须由不同人员担任。没有助理裁判员及第四官员岗位。
- 是否需要裁判监督仍可独立选择；监督沿用现有规则，可兼任任一场上岗位，也可为非系统裁判。
- 裁判员填写比赛报告，同时填报本人和第二裁判员的完整执裁数据。五人制不显示、不接受助理裁判员的越位举旗次数与协助次数。计时员没有执裁数据表，仅接受监督评分。
- 五人制附件显示为“比赛记录单”。普通比赛保持原报告字段与附件名称。
- 任一报告分区开始后不能切换安排类型；开始前切换须明确确认。保留仍适用的选派和报名意向，清空不适用项；某条有效报名意向全部失效时自动撤回，追加变更历史，裁判可按新岗位重新报名。
- 手机、桌面页面，管理员选派候选，个人赛程、统计与监督评分、报告历史和 CSV 导出均支持新岗位。

## 复跑与后续升级

使用配置好的独立测试数据库连接，在 `backend` 目录执行：

```text
npm run test:futsal
npm run test:e2e:futsal
npm run test:migration:futsal
npm run preview:futsal
```

测试与预览沿用现有随机隔离测试库机制。当前机器的独立 MySQL 启动与连接辅助脚本在本机忽略文件 `.cache/futsal-local.cjs`，不包含生产配置。日常 `TJRefWebMySQL` 服务曾在首轮测试时异常退出，用户启动服务后已确认恢复；最终验收和当前预览使用独立实例。

正式部署将前端、后端与0033迁移配套发布，沿用 `deploy/PRODUCTION.md` 的备份、停服、增量迁移、启动与验收流程。本次已按此流程上线；新版本产生五人制数据后，旧应用不能完整识别新岗位，应使用前向修复或配套备份恢复。
